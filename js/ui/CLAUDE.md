# CLAUDE.md — 프론트엔드 (동제)

루트 `CLAUDE.md`의 공통 계약이 먼저다. 이 문서는 그 위에 얹는 담당 규칙이다.

## 담당

`index.html`, `style.css`, `js/ui/ui.js` — 화면 전부.

**세 명 중 유일하게 루트 파일을 건드린다.** `index.html`은 세 명 다 script 태그나 버튼을 넣고 싶어하는
파일이라 충돌 위험이 가장 높다. **뼈대를 가장 먼저 만들어 올려야** 나머지 두 명이 기다리지 않는다.

## 가장 먼저 할 일

`index.html` 뼈대 + script 태그 3개를 만들어 **10분 안에 커밋한다.**

```html
<script src="js/store/store.js"></script>
<script src="js/analytics/analytics.js"></script>
<script src="js/ui/ui.js"></script>
```

- **`type="module"` 금지.** `file://`에서는 CORS로 차단돼 화면이 백지가 되고, 콘솔 에러도 알아보기 어렵다
- 순서를 지킨다. `ui.js`가 마지막이다
- 파일이 아직 비어 있어도 된다. 빈 파일 3개를 만들어두면 404가 안 뜬다

## 책임

- 마크업, 스타일, DOM 렌더링, 이벤트 바인딩
- `Store` / `Analytics` 호출과 결과 표시
- 사용자에게 보이는 문구 — 에러 메시지 배치, 빈 목록 안내, 단위 표기

## 경계

- **localStorage를 직접 만지지 않는다.** 항상 `Store`를 거친다
- 검증을 직접 짜지 않는다. `Store.add()`가 돌려주는 `errors`를 화면에 뿌릴 뿐이다
  - `required`, `max`, `min` 속성은 넣어도 된다. 편의일 뿐 방어선이 아니다
  - `<input type="date" max="오늘">`을 넣되, 통과해도 `Store`가 다시 막는다
- 집계를 직접 계산하지 않는다. `Analytics`를 호출한다

`Store.add()` 반환값 처리:

```js
const r = Store.add(input);
if (!r.ok) { /* r.errors의 각 필드 옆에 메시지 표시 */ return; }
render();
```

## 화면 순서 (명세서 준수)

과제는 **활동 기록 관리 웹앱**이다. 다이어트 시각화가 아무리 예뻐도 필수 3기능을 밀어내면 안 된다.
심사자가 스크롤해서 찾아야 하는 순간 지는 것이다.

첫 화면(스크롤 없이)에 이 순서로 들어간다.

```
1. 활동 등록 폼          ← 명세 필수 ①
2. 오늘의 체중 + 눈금 트랙  ← 시그니처. 폼 옆이나 바로 아래
3. 활동 목록             ← 명세 필수 ②③. 스크롤 없이 최소 3건은 보인다
--- 스크롤 ---
4. 통계 (월별 / 카테고리 / 칼로리 수지)
5. JSON 내보내기·가져오기, 샘플 데이터 버튼
```

- 체중 숫자는 크게 가되 **화면을 독점하지 않는다.** 히어로가 화면 전체를 먹는 랜딩페이지 구성을
  따라가면 안 된다 — 우리는 도구다
- **장소와 참여 인원 입력란을 빼지 않는다.** 개인 기록처럼 보여도 명세 필수 입력이다
- 목록의 각 행에 활동명·날짜·장소·참여 인원이 **전부 보여야 한다.** 체중만 보이는 행은 안 된다

## 필수 요건 (감점 직결)

- 목록은 **최신순**
- 저장된 활동이 0건이면 **안내 문구**를 띄운다 (빈 화면 금지)
- 삭제는 **확인 절차**를 거친다 — `confirm()`이면 충분하다
- 에러 메시지는 어느 필드가 잘못됐는지 알 수 있게 보여준다. `alert("입력 오류")` 한 줄은 부족하다

## 디자인 방향 — "저울과 라벨"

다이어트 앱은 전부 파스텔 민트에 둥근 카드다. **정반대로 간다.**

이 앱이 다루는 물건은 두 개다 — **체중계**와 **식품 영양성분표**. 둘 다 고유한 시각 언어가 있고,
둘 다 "숫자를 정확하게 읽히게" 만들도록 설계된 물건이다. 화면을 그 언어로 만든다.

- 화면 전체가 **한 장의 라벨**이다. 단일 컬럼, `max-width: 720px`, 좌측 라벨 / 우측 값
- 위계는 **선 두께**가 만든다. 영양성분표가 그렇게 한다. 색이나 크기로 대신하지 않는다
- 색은 거의 쓰지 않는다. **빨강은 아날로그 체중계의 바늘 하나**뿐이고 "오늘"에만 쓴다

### 레퍼런스 조사 (Dribbble 인기 웹디자인 상단 4건)

실제로 열어본 것: Pallet Ross(아트마켓), SAPFORCE(디자인툴), Immediate(급여), NexusSci(연구플랫폼).
넷 다 랜딩페이지다. **우리는 폼과 목록이 있는 기록 도구다** — 히어로 구성은 따라가면 안 되고,
아래 넷의 공통 시스템만 가져온다.

**가져온 것**

1. **바깥 캔버스 위에 떠 있는 패널.** 네 개 전부 그렇다. 배경이 한 톤 다르고 본문이 라운드 사각형
   안에 얹혀 있다. 우리 컨셉과도 맞는다 — 영양성분표는 포장지 위의 흰 패널이고, 저울 액정은
   하우징에 박힌 판이다. 트렌드를 갖다 붙이는 게 아니라 컨셉을 더 밀어준다
2. **디스플레이 타입을 더 키운다.** 넷 다 내가 잡았던 것보다 크다. 화면에서 가장 큰 것이 오늘 체중이다
3. **단색조 팔레트.** Immediate는 초록 하나, SAPFORCE는 회색 하나로 끝낸다. 색 가짓수가 아니라
   명암으로 위계를 만든다 — 이미 우리 방향이다
4. **주석 칩.** 히어로 위에 작은 라벨이 떠 있다(`@coplin`, `The world's best...`).
   우리는 이걸 **눈금 위 콜아웃**으로 쓴다 — `최저 66.2` / `오늘 68.4`

**버린 것 (이유 있음)**

- **알약 버튼·알약 네비게이션** — 넷 다 `border-radius: 999px`다. 우리는 안 쓴다.
  표의 숫자를 읽히게 만드는 게 이 화면의 일이고, 둥근 알약은 그 격자를 무너뜨린다.
  둥글게 하는 순간 흔한 다이어트 앱이 된다. **여기서 선을 지킨다**
- **3D 오브젝트·그라디언트 메시** — 만들 시간도 없고, 데이터가 주인공인 화면에 장식이다
- **`/01 /02 /03` 슬래시 번호 목록** — 우리 콘텐츠는 순서가 아니다. 순서가 아닌데 번호를 붙이면
  거짓 정보를 주는 것이다

### 토큰

```css
:root {
  --canvas: #C4CFBE;              /* 바깥 캔버스. 패널이 이 위에 뜬다 */
  --paper:  #E9EBE4;              /* 저울 하우징 = 패널 바탕 */
  --lcd:    #B4C3AD;              /* 액정 바탕 */
  --ink:    #161D18;              /* 세그먼트 잉크 */
  --ink-60: rgba(22, 29, 24, .6);
  --ink-25: rgba(22, 29, 24, .25);
  --needle: #D8342A;              /* 바늘. 이 색은 '오늘' 표시에만 쓴다 */

  --rule-section: 8px;            /* 섹션 경계 */
  --rule-group:   3px;            /* 그룹 경계 */
  --rule-row:     1px;            /* 행 구분 */

  --panel-radius: 4px;            /* 패널 모서리만 살짝. 그 안은 전부 각지게 */
}
```

레이아웃: `body`에 `--canvas`, 그 안에 `max-width: 760px`인 `--paper` 패널을 `margin: 40px auto`로
띄운다. 모바일에서는 여백을 `16px`로 줄인다. **패널 안의 요소에는 `border-radius`를 쓰지 않는다.**

`--needle`을 두 군데 이상 쓰고 싶어지면 잘못 가고 있는 것이다. 증감은 색이 아니라
**바늘 위치와 삼각형 방향(▲▼)** 으로 나타낸다. 빨강/초록 증감 표시는 쓰지 않는다.

### 타이포

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Archivo:wdth,wght@62..125,400..900&family=IBM+Plex+Mono:wght@400;600&family=IBM+Plex+Sans+KR:wght@400;600&display=swap" rel="stylesheet">
```

| 역할 | 서체 | 용도 |
|---|---|---|
| 디스플레이 | `Archivo` — `font-stretch: 68%`, `font-weight: 800` | 큰 숫자, 섹션 제목. 좁고 굵게 눌러 라벨 느낌을 만든다 |
| 본문(한글) | `IBM Plex Sans KR` 400/600 | 라벨, 설명, 버튼 |
| 데이터 | `IBM Plex Mono` 400/600 | 표의 숫자 전부 |

- 숫자에는 반드시 `font-variant-numeric: tabular-nums`. 자릿수가 안 맞으면 라벨처럼 안 보인다
- 폰트는 CDN이라 **네트워크가 끊기면 대체 서체로 떨어진다.** 레이아웃은 그대로 서야 한다.
  `font-family: Archivo, system-ui, sans-serif` 처럼 폴백을 반드시 적는다
- 오늘의 체중 숫자는 `clamp(4.5rem, 16vw, 8.5rem)`. 화면에서 제일 큰 것이 체중이고,
  레퍼런스들이 전부 이 정도로 키운다. 어중간하게 크면 그냥 큰 글씨고, 확실히 키워야 구조가 된다
- 단위(`kg`)는 숫자의 1/4 크기로 붙여 쓴다. 숫자가 주인공이고 단위는 각주다

### 시그니처 — 눈금 트랙

**이 화면이 기억되는 단 하나의 요소.** 체중 추이를 가로 눈금자 위에 바늘로 얹는다.

```css
.ruler {
  height: 48px;
  background: var(--lcd);
  background-image: repeating-linear-gradient(90deg, var(--ink-25) 0 1px, transparent 1px 4%);
}
.ruler__needle {
  width: 2px; height: 100%;
  background: var(--needle);
  transition: left .2s ease;
}
@media (prefers-reduced-motion: reduce) { .ruler__needle { transition: none; } }
```

- 바늘 위치 = `(오늘체중 - 최저) / (최고 - 최저) * 100%`
- 기록이 1건이면 최고=최저라 **0으로 나눈다.** 이때는 바늘을 가운데(50%)에 둔다
- 목록의 각 행에도 같은 눈금을 얇게(높이 6px) 깔면 그날 체중이 범위 어디였는지 보인다.
  이게 이 디자인의 리듬이다 — 여유가 없으면 상단 큰 눈금 하나만 해도 성립한다

### 움직임

바늘 이동 `.2s` **하나뿐이다.** 그 외 애니메이션은 넣지 않는다.
움직임이 많을수록 AI가 찍어낸 화면처럼 보인다.

## 통계 화면

**차트 라이브러리를 쓰지 않는다.** CDN은 규정상 허용되지만 행사장 네트워크가 끊기면
화면이 통째로 죽고, Chart.js 축·옵션 맞추는 데 30분이 날아간다.
위 눈금 트랙과 CSS 막대(`width: {비율}%`)면 10분이고, 디자인 방향에도 맞는다.

표시할 것:
- `Analytics.weightTrend()` → **눈금 트랙**. 화면 최상단, 가장 큰 요소
- `Analytics.kcalBalance()` → 날짜별 섭취 / 소모 / 수지 표. 수지는 `+`/`-` 부호로
- `Analytics.summary()` → 라벨 하단 합계 행 (영양성분표의 굵은 선 아래처럼)
- `Analytics.monthlyCount()` / `byCategory()` → 가로 막대

**칼로리 소모는 추정치다.** 화면에 "운동 시간과 종목으로 추정한 값" 한 줄을 적는다.
값이 없는 날은 `0`이나 `NaN`이 아니라 `—` 로 표시한다.

## 문구

- 버튼은 일어날 일을 그대로 적는다. `제출` 아님 → **`기록 저장`**. 저장 후 안내도 `저장했습니다`로 맞춘다
- 빈 목록: `아직 기록이 없습니다. 오늘 체중부터 남겨보세요.` — 빈 화면은 안내가 아니라 **초대**다
- 에러는 사과하지 않고 무엇을 고칠지 말한다. `참여 인원은 1명 이상이어야 합니다`
- 문장형 대소문자, 과장 없이. 라벨은 라벨만 하고 설명을 겸하지 않는다

## 샘플 데이터 버튼

- 누르기 전에 `confirm()` — 몇 건이 생기는지 알린다
- 자동 실행 금지. 페이지 로드 시 몰래 채우지 않는다
- 샘플 기록은 화면에서 구분되게 표시한다 (`memo`의 `[샘플]` 표시를 배지로 보여주면 된다)

## 하지 말 것

- `type="module"` 사용
- `localStorage` 직접 접근
- 검증 로직을 `ui.js`에 중복 구현
- 담당 폴더 밖 파일 수정 — `store.js`나 `analytics.js`가 안 돌아도 **직접 고치지 않는다.** 담당자에게 말한다
- 차트 라이브러리 도입 (필수 기능이 다 끝난 뒤가 아니면)
- 데모 시나리오에 없는 화면 만들기

## 검증 방법 (커밋 전 직접 확인)

크롬으로 `index.html`을 열고 손으로 확인한 뒤, 결과를 커밋 본문에 한 줄로 남긴다.

- 활동명 비우고 저장 → 막히고, **활동명 옆에** 메시지가 뜨는지
- 날짜를 내일로 → 막히는지
- 참여 인원 `0` / `-1` / `2.5` → 각각 막히는지
- 저장 → 목록 **맨 위**에 뜨는지
- 전부 삭제 → 빈 목록 안내 문구가 뜨는지
- 삭제 → 확인창이 뜨고, 취소하면 안 지워지는지
- 데이터 0건에서 통계 화면 → `NaN` / `Infinity` / 빈 막대가 안 보이는지
- 콘솔에 에러가 없는지

## 작업 순서

1. `index.html` 뼈대 + script 태그 3개 + 빈 js 파일 3개 → **커밋** (최우선, 10분)
2. 등록 폼 마크업 + `Store.add` 연결 + 에러 표시 → **커밋**
3. 목록 렌더링 (최신순, 빈 목록 안내) → **커밋**
4. 삭제 + 확인창 → **커밋**
5. `style.css` — 읽을 수 있는 수준까지만 → **커밋**
6. 통계 화면 (CSS 막대) → **커밋**
7. 샘플 데이터 버튼 → **커밋**

**1번이 늦으면 팀 전체가 멈춘다.** 다른 걸 먼저 하지 않는다.
2~4번(필수 기능)이 끝나기 전에는 5~7번에 손대지 않는다.
